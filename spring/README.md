직접 만든 연습 자료입니다. 실제 기업의 평가 문제나 출제 예상 문제가 아닙니다.

## 준비됐을 때 진행할 과제

**15–25분** 동안 새로 추가되는 `PurchaseService.java`를 리뷰하세요. 이 파일의 36줄 전체가 PR 변경 사항입니다. `CONTRACTS.md`는 변경되지 않은 기존 코드와 환경에 대한 설명입니다. 코드를 구현하거나 지금 바로 퀴즈를 진행할 필요는 없습니다.

**우선순위가 가장 높은 리뷰 의견 두 개**를 작성하세요. 각 의견에는 다음 내용을 포함하세요.

1. 위치: 파일과 줄 번호 또는 해당 표현식
2. 문제가 발생하는 구체적인 상황
3. 사용자·비즈니스에 미치는 영향과 우선순위
4. 문제를 해결할 수 있는 최소한의 수정
5. 수정 전에는 실패하고 수정 후에는 통과할 테스트 하나

마지막에 승인 / 변경 요청 중 하나를 선택하고 이유를 한 문장으로 적으세요. 가능한 문제를 모두 찾을 필요는 없습니다. 실제로 발생할 수 있음을 설명한 문제와 선택적인 개선 사항을 구분하고, 큰 구조 변경은 피하세요. 계약과 전제 이해에 약 5분, 시나리오 분석에 10–15분, 리뷰 의견 작성에 5분을 쓰면 됩니다.

## PR 설명

> 고정 가격 상품의 구매 기능을 추가합니다. 재고를 확인하고 테스트용 결제 컴포넌트로 구매를 승인받은 뒤, 재고를 갱신하고 구매 결과를 반환합니다. HTTP 인터페이스는 기존 컨트롤러와 예외 처리기가 담당합니다.

## 제품 요구사항

- 로그인한 구매자는 자신의 계정으로만 구매할 수 있습니다. 이 엔드포인트는 선물하기, 대리 구매, 관리자 예외 권한을 지원하지 않습니다.
- 가격의 기준은 서버에 저장된 상품 가격입니다. `unitPrice`는 클라이언트 화면에 표시된 가격이므로 오래되었거나 변조되었을 수 있습니다. 현재 상품 가격으로 구매 금액을 계산해야 합니다. 이 연습에는 할인, 수수료, 세금, 환전이 없습니다.
- 구매가 승인되면 가용 재고는 구매 수량만큼 정확히 한 번 줄어야 합니다. 마지막 한 개를 동시에 구매하려는 요청이 들어와도 초과 판매가 발생하면 안 됩니다.
- 결제가 거절되면 구매 내역이 생성되지 않아야 하며 재고도 그대로여야 합니다. 실패한 구매 처리에 속하는 데이터베이스 변경은 커밋되면 안 됩니다.
- 구매 성공 시 `PurchaseView`와 HTTP 201을 반환합니다. 형식은 유효하지만 재고가 부족한 요청은 409, 결제 거절은 422, 없는 상품은 404, 인증되지 않은 요청은 401입니다. 다른 계정 명의로 구매하려는 요청은 403이어야 합니다.

## 범위와 실행 제한

이 자료는 실행 가능한 Spring Boot 프로젝트가 아닌 **코드 리뷰 전용 예제**입니다. 리뷰 전에 `CONTRACTS.md`를 읽으세요. 애플리케이션, 빌드 파일, 데이터베이스, 서버 대신 의존 컴포넌트의 동작을 설명해 두었습니다. Java 파일은 컴파일하거나 통합 테스트하지 않았으며, 단독으로 빌드할 수 없습니다. 테스트는 말로 설계해도 됩니다. 연습을 위해 프로그램 설치, 외부 계정, 실제 결제, 데이터베이스 설정을 할 필요는 없습니다.
