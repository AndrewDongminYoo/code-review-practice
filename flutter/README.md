# 모의 PR 2 — 스튜디오 검색 컨트롤러 (Flutter)

**권장 시간: 15–20분.** 미리 준비해 둔 연습 자료입니다. 연습을 시작하고 싶을 때 열어보세요. 가상의 코드 리뷰 문제이며, 특정 회사의 실제 평가 내용을 예측한 자료는 아닙니다.

## PR 설명

> 스튜디오 탐색 화면에 검색과 재시도 기능을 추가합니다. 사용자는 검색 결과에서 스튜디오를 선택한 뒤 별도의 예약 페이지로 이동합니다. 상태는 작은 ChangeNotifier 컨트롤러에서 관리하고, 위젯은 화면 표시만 담당하도록 구성했습니다.

`search_controller.dart` 전체가 이번 PR에서 추가된 코드라고 가정하고 리뷰하세요. `studio_repository.dart`에는 필요한 저장소 인터페이스와 모델의 전체 계약이 들어 있습니다. 저장소 복제, 계정, 설치, 네트워크 요청 없이 읽고 검토할 수 있습니다.
이 과제 설명은 원본 결함 코드에 해당합니다. 현재 브랜치의 컨트롤러에는 리뷰 지적에 따른 수정이 반영되어 있으며, 원본 파일은 첫 커밋 `17d774b`에서 확인할 수 있습니다.

## 제품 동작 및 UI 계약

- 화면 하나가 컨트롤러 하나를 소유합니다. 화면이 제거되면 소유자가 `dispose()`를 한 번 호출합니다. 저장소의 소유권은 다른 곳에 있으므로 이 컨트롤러가 저장소를 닫아서는 안 됩니다.
- 검색어를 제출할 때마다 `search(text)`를 호출합니다. 로딩 중에도 검색을 제출할 수 있으며, UI는 이전 호출이 끝나기를 기다리지 않습니다. 모든 호출은 UI isolate에서 실행됩니다.
- 결과는 가장 최근에 제출한 검색어와 일치해야 합니다. 새 검색을 시작하면 이전 결과를 즉시 비우는 것이 의도된 동작입니다.
- 지우기 버튼은 `clear()`를 호출합니다. 이는 “검색 전의 빈 화면으로 초기화”한다는 뜻이며, 검색을 새로 요청하지 않습니다. 반면 사용자가 빈 검색어를 직접 제출하면 “전체 스튜디오 표시”를 뜻합니다.
- UI는 `loading`이면 로딩 표시를 보여줍니다. 로딩이 아니라면 `error != null`일 때 재시도 버튼이 있는 오류 패널을, 그 외에는 스튜디오 목록 또는 결과 없음 화면을 보여줍니다. 입력과 지우기 기능은 모든 상태에서 사용할 수 있습니다.
- 재시도는 현재 검색어를 사용합니다. 재시도가 성공하면 정상적인 결과 화면으로 돌아와야 합니다.
- 요청이 진행되는 동안 사용자가 다른 화면으로 이동할 수 있습니다. 컨트롤러가 폐기된 뒤에는 UI 콜백이 이 컨트롤러를 호출하지 않지만, 이미 시작한 작업은 이후에 완료될 수 있습니다.
- 리스너는 위젯을 다시 그리는 역할만 하며, 컨트롤러 메서드를 동기적으로 호출하지 않습니다. 위젯과 저장소 구현은 리뷰 범위에서 제외합니다.
- 저장소 계약상 실패는 `SearchUnavailable`로만 표현됩니다. 인증, 서버 검색의 정확성, 예약 제출은 이번 리뷰 범위가 아닙니다.
